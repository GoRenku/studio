# Use First-Class Props As Continuity Subjects

Date: 2026-07-30

Status: accepted

## Context

Production Design previously stored recurring objects only as local entries
inside Location Design JSON. That shape preserved location dressing notes but
could not give a recurring Prop durable identity, independent design history,
exclusive media ownership, generation targets, or a bookmarkable Studio
surface.

## Decision

Add `Prop` as a first-class ordered project fact with durable id, handle, name,
description, and visual notes. Add immutable Prop Design history with one
active design per Prop. Location Design retains location-local
`recurringObjects`; those entries are not inferred, promoted, or linked to
Props automatically.

Core owns Prop facts, design validation and persistence, delete dependencies,
navigation/resources, Asset ownership and canonical Hero selection, generation
purposes, destinations, Preview facts, attachment, and structured diagnostics.
CLI and Studio remain thin callers.

Prop media uses exclusive Prop ownership:

- `prop_sheet` Assets are request-scoped references generated by `prop.sheet`;
- `prop_hero` Assets may have one owner-scoped canonical selection and are
  generated by `prop.hero`;
- Prop Sheets never gain a global selection;
- prior same-Prop sheets are explicit candidates and are never chosen
  automatically.

Files use flat, versioned paths:

```text
props/<prop-handle>/prop-sheets/<sheet-slug>.<ext>
props/<prop-handle>/heroes/hero.<ext>
```

Studio exposes Props below Locations and above Scenes, with URL-owned overview
and detail routes. Cast, Location, and Prop resource reads share the
`/continuity` HTTP boundary; the obsolete Cast and Location screenplay routes
are removed directly.

Migration 0070 adds the Prop tables and performs a guarded one-way Location
Design JSON rename from the former recurring-object key to
`recurringObjects`. It aborts malformed or ambiguous documents rather than
guessing.

## Consequences

- Props can participate in continuity, media generation, Preview, selection,
  navigation, and agent workflows without being screenplay entities.
- Prop facts and Prop Design stay separate from prompts and generated media,
  whose creative contents remain opaque to Studio runtime code.
- Location recurring objects remain useful local set-dressing notes.
- No compatibility aliases, inferred migrations, shared Assets, or automatic
  media promotion are introduced.
- Production Designer owns Prop authoring direction and hands focused media
  work to Media Producer.

## Update Notice: Screenplay References

Decision 0071 extends first-class Props into the Scene-first Screenplay
reference model. Props remain independent Project facts; Screenplay and Beat
Sheet records may reference their durable ids without embedding or duplicating
Prop facts.
