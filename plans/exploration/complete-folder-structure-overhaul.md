## Key Conventions
The file and folder naming will follow these key conventions for consistency.
- We always use kebab-casing for file and folder names.
- We prefer simplicity in file naming and strive for removing additional things from the name when the context (folder path) makes it clear and they are not likely to be used in a flat folder.

### File naming
- File naming follows this format (see variants section below for g and v)
semantic-name-gXX-vXX

Semantic Names Per Object Type
- Lookbook Image: short-max-5-word
  - Use the same naming scheme no changes
- Drag-drop (imported) Inspiration images
  - Use the same renaming scheme no change (still-000-some-hash)
- Character Sheet: character-name-variation-sheet
  - character-name: The name of the character in kebab-case
  - variation: This should be one or max 2 word semantic descriptor for character sheet. This can indicate particular wardrobe, particular purpose etc. For example: for Mehmed, the sheet ids can be "armor", "palace-robe" etc.
  - sheet: denotes character sheet
  - E.g.: saruca-palace-robe-sheet
- Profile: character-name-profile
  - character-name: The name of the character in kebab-case
  - profile: denotes that this is the profile image of the character
  - E.g. constantine-xi-profile
- Voice sample: character-name-sample-descriptor
  - character-name: The name of the character in kebab-case
  - sample-descriptor: This is a max 2 word that describes the sample of that voice. It could be things like shouting, whishpering, default (just basic talking)
  - E.g.: mara-whispering
- Location Sheet: location-name-variation-sheet
  - location-name: The name of the location in kebab-case. Only the first 2 words of location
  - variation: This should be one or max 2 word that denotes a variation of the location. E.g. "dusk", "burned-down", ...
  - sheet: denotes the location sheet
- Location Hero: location-name-hero
  - location-name: The name of the location in kebab-case. Only the first 2 words of location
  - hero: denotes that this is a hero image
- Prop Sheet: prop-name-variation-sheet
  - Same as in location but instead props
- Prop Hero: prop-name-hero
  - Same as in location but instead props
- Scene-dialog-audio: scene-number-character-dialog-number
  - scene-number: denotes the scene number starting with s: E.g. s01 (scene 01)
  - character: first name of the character
  - dialog-number: denotes the dialog number in the scene starting with d: E.g. d02 (dialog 2). The number is the consecutive dialog number and not specific to the character
  - E.g s01-mara-d01 denote scene 1, mara, speaking 1st dialog in that scene (we use s and d to denote scene and dialog#)
- Storyboard Image: scene-number-beat-number-image
  - Storyboard images are based on beats. They are generated by Renku. The beats are not part of the original screenplay so they are solely owned by Renku. The beat numbers generation should follow the same numbering scheme as scene numbering generation but beat numbers are always created by Renku as it is the source of truth. Adding new beats should not disturb the order. If a scene's beats are reset and generated from scratch than it uses a clean new numbering system. The full (reset) beat generations gets an iteration folder (see folders section below)
  - scene-number: denotes the scene number starting with s: E.g. s01 (scene 01)
  - beat-number: denotes the beat number starting with b: E.g. b01 (beat 01)
  - E.g.: s01-b01-image denote image for scene 1, beat 1.
- Shot image: shot-number
  - Shot images are stored in a folder hierarchy that reflects the scene and plan and therefore we do not prepend those. They are also never used outside their plan and scene.
  - shot-number: denotes the shot number in the plan with shot: E.g. shot01
  - E.g.: shot01 denotes image for shot 1 (for the plan and scene in the folder they are in)
- Reference images (first & last frame): first-frame or last-frame
  - E.g.: first-frame denotes first frame image for the scene and shot plan folder they are stored in.
- Reference images (video-storyboard): storyboard
  - E.g.: storyboard denotes storyboard image for the scene and shot plan folder they are stored in.
- Reference images (custom reference): reference
  - E.g.: reference denotes reference image for the scene and shot plan folder they are stored in.
- Videos: scene-number-shot-plan-number-video
  - The videos are likely to be exported for post processing so we do store scene and shot-plan number as part of the video filename.
  - scene-number: denotes the scene number starting with s: E.g. s01 (scene 01)
  - shot-plan-number: denotes the shot plan number starting with p: E.g. p01 (plan 01)
  - E.g.: s01-p01-video denotes video for scene 1, shot plan 1

### Variants
For a given semantic object (character sheet, profile image, shot image, dialog audio, shot plan video etc.), we can create:
- External attachment: These are retrieved externally and attached. Note that this does not include the Codex generated images as they are still generated. But includes images that are retrieved from an external system (Internet, ...) For these we simply keep the existing filename of the asset.
- Multiple generations: These are essentialy different from scratch takes on generating that semantic object. They can happen concurrently. We denote this with a "g" followed by the generation number (2 digits starting with 01: 01, 02, .. 10, 11).
- Edits/Iterations: These are edits on a given generated asset. The asset is also used as an input and some aspect of it is edited or regenerated. We denote this with a "v" followed by the version number (Same as generations).
  - Until there is an edit we do not append a "v" to make the file names less cluttered and because edits are relatively rare.

Examples:
- Shot Image (generation 1, no edit)
  - shot01-g01.png
- Cast Profile Image (generation 1, edit 2)
  - constantine-xi-profile-g01-e02.png

### Folder hierarchy
- visual-language
  - inspiration
    - name-of-inspiration (unchanged from existing implementation)
      - flat list of imported images
  - lookbooks (now plural)
    - production
      - flat list of lookbook images
    - storyboard
      - flat list of lookbook images
- cast
  - cast-name (flat containing the profile and sheet images and sample voice. DO NOT USE SUBFOLDERS for sheets, ...)
    - E.g.: mara-whispering.mp3
- locations
  - location-name (flat containing the hero and sheet images. DO NOT USE SUBFOLDERS for sheets, ..)
- props
  - prop-name (flat containing the hero and sheet images. DO NOT USE SUBFOLDERS for sheets, ..)
- storyboards (We do not use sequence number folders anymore, just scene numbering)
  - scene-number (E.g. 01)
    - number-iteration (E.g. 00-iteration This is a flat folder with all the beat images for that beat generation images)
      - E.g. s01-b01-image.png
    - tmp (As before contains the sheets of images generated for performance reasons internally)
- scenes
  - scene-number (E.g. 01)
    - dialogues (all dialogs for the scene)
      - E.g. s01-mara-d01-g01.mp3
    - shot-plan-number (E.g. 01)
      - shot-images (all the shots in the shot plan)
        - E.g. shot01-g01.png
      - number-generation (E.g. 02-generation We store the reference images and videos.)
        - E.g. first-frame-g01.png (notice the g01 here denotes the reference image generation and not the video generation whereas the containing folder has the video generation)
        - E.g. s01-p01-video-g02.mp4 (g02 does not match the first frame generation on purpose but it matches the number generation of its containing folder)
- tmp (temp folder for spec proposal JSON files)
