# Data Model
Renku is a tool for hybrid film making that is intended for pre-production and production (not post production)
- It can be used to make films using traditional film making and helping define the pre-production. 
- It can be used for pure AI film making where the shots are generated using AI tools.
- And more importantly it can be used in hybrid film making, where some shots are generated and some shots are filmed. 

Therefore we need to get the terminology right and not confuse traditional filmmaking concepts with concepts from AI filmmaking. So here are the definitions we will be using:

*Beat*: an atomic narrative development.
*Shot*: an atomic editorial interval between cuts.
*Attempt*: one execution intended to create one shot, several shots, or a sequence.
*Take*: a camera-based attempt. Same definition as in traditional film making. TBD for later
*Generation*: an AI-based attempt.
*ShotPlan*: an ordered collection of shots or a single shot planned for a take or generation.
*Asset*: the file produced by an attempt.

- A beat belongs to a story narrative, and represents changes inside a scene. We already represent them in Renku as beats of a scene. No changes needed there
- A beat can have many shots that represent it, or alternatively it is possible to span multiple beats through a continuous shot. Beats within Renku are useful for providing the context to the user and AI in designing the shots. But apart from just recording what beat(s) a shot represents, there should be no other a relationship. There is also no point representing a relationship from a beat to the shot(s). The relationship is one directional and should not try to have deeper understanding into the contents of the beat. Shot -> 1:more -> Beat
- Given a shot, we should know what Beat/Scene it is representing. 

The key here is that we separate out the execution step as it can be done via traditional or AI generated means. Therefore we will not use Takes as the general term for trying different things (as represented by assets of video files). We will use a Renku term called Attempt instead with 2 different types: Take (for traditional film making) and Generation (for AI filmmaking)

When a user wants to film (generate or shoot) a beat, a set of beats or parts of a beat, what they create is an *attempt*. If it is a traditional film making than the attempt is called a *take* or if it is an AI generated attempt than it is called a *generation*.

- An attempt can have multiple shots or a single one and each shot is defined by its *setup*. 

## Shot Plan
A shot plan contains one or more ordered shots. The narrative coverage is defined for the shot plan and the setup is defined per shot in the shot plan. 

*ShotPlan* is a table in sqlite with following columns:
- id
- scene -> scene id 
- title (generated by Agent AI during creation)
- narrativeCoverage -> A JSON field that contains the beat numbers in the scene (in scene_beat_sheet) E.g. [1, 2, 3]
- status (values of which)
  - Concept (when the AI agent first generates)
  - Ready (Indicates its readiness for shooting or generation)
  - Produced (meaning there is an asset generated or attached for this)

The context for the shot is retrieved from the scene it belongs to. (e.g. the information about the beats, location, the cast members, the scene dialog etc.) 

## Shots
The shots belong to a shot plan. They are represented in sqllite table shots as such:
- id
- shotPlan -> a shot plan id
- order -> canonical order of the shot in the plan
- description -> See below
- brief -> See below

### Description
- We will make the *description* intentionally as a markdown document and not a structured set of fields to be defined. Here is an example of a detailed shot definition:
```
The shot lasts approximately ten seconds and is captured on an 85 mm lens on a full-frame camera at T2.0, giving Anna a compressed, intimate close-up with a shallow depth of field. The camera begins at her eye level, approximately 2.5 metres away, in a medium close-up from the chest upward. Anna is positioned on the right third of the frame beside the window. Ben is seated closer to camera on the left, visible only as a soft, dark foreground silhouette that frames Anna without drawing attention away from her.

Anna holds the unopened letter in her left hand at the lower edge of the frame. She opens it and begins reading. The camera remains still for the first three seconds, allowing the action to settle. As Anna reaches the first line and her expression begins to change, the camera makes a slow, nearly imperceptible dolly push of approximately 60 centimetres, tightening from the medium close-up to a close-up. The movement should feel motivated by her realization rather than noticeable as a camera move.

Focus remains on Anna’s eyes throughout the shot. Because of the shallow depth of field, the letter is identifiable but its text is not readable, while Ben remains heavily defocused in the foreground. The focus puller should make a subtle adjustment during the push to maintain sharp focus on Anna as the camera closes the distance.

The primary light is cool, soft daylight entering through the window to Anna’s left. It is diffused through a large frame outside the window so that it wraps gently across her face without producing hard shadows. Negative fill on camera-right deepens the shadow side of her face and gives the image more contrast as her mood changes. A dimmed tungsten desk lamp at approximately 2800K creates a warmer pool of light on the letter and her hands. The camera is white-balanced around 4300K so that the window light remains slightly cool while the practical lamp retains a visible warmth.

Anna should begin the shot calm and focused on the envelope. Her reaction must develop gradually rather than appearing immediately: recognition, disbelief, and then stillness. She freezes briefly after reading the first line, lifts only her eyes toward Ben, and then raises her head. The camera completes its push at the exact moment she looks at him.

The shot ends with Anna in close-up, looking screen-right toward Ben. She must keep the letter in her left hand throughout, the desk lamp must remain visible behind her, and Ben must remain on the left side of the frame to preserve the scene’s established eyeline and screen direction.
```

### Brief
- We will have a very minimal (yet extensible) set of highlighted structured information about the shot called the *brief*. These act like tags and are used as a way to render the UI so the user can at a quick glance see some important properties of the shot
  - These are also all optional and not required for a shot to be valid. 
```json
{
  "durationSeconds": 10,
  "framing": {
    "start": "medium close-up",
    "end": "close-up"
  },

  "camera": {
    "angle": "eye level",
    "movement": "very slow push-in"
  },

  "optics": {
    "focalLengthMm": 85,
    "depthOfField": "shallow",
    "focusTarget": "Anna's eyes"
  },

  "lighting": {
    "key": "soft cool window light",
    "accent": "warm desk-lamp practical"
  },
}
```

## Generation
A *generation* (AI attempt) contains the following info:
- prompt for the generation. This is created using the *shot description*. The models have different needs for how a shot prompt should be defined. Also in some case a shot can be defined visually as a storyboard progression (see video story board sheet below). Also sometimes we provide first and last frames, or other reference images, so the shot does not need some of the narrative description either.
- model configuration
- optional character sheets that define the actors in the shot 
- optional location sheet for the location of shot
- optional lookbook (production or storyboard). Note it should be possible to create generations with storyboard visual style as well.
- optional dialogue audio for voice consistency in dialogs.
- optional first/last frame images for those types of AI generation requests
- optional video story board sheet to aid a generation with multiple shots that represents each shot as an image and explanation in a grid style format.
- optional video that depicts the shot (or shots) using 3D mock previs of the characters, their environment and camera movements
- optional images, audio or video that the user sees fit that may help in generating this particular attempt

A scene can have multiple shot plans, with different shots owned and contained in their definitions. This give maximum flexibility so that users can create different shot plans either for traditional film making or AI generations. Each AI generation can have its own shotlist as well.
